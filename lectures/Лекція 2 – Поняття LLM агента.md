## Що не так з LLM?

| Проблема | Опис |
|---|---|
| **Застарілі дані** | Знання зафіксовані на момент навчання. Немає доступу до актуальної інформації |
| **Немає дій** | Не може виконувати операції у зовнішньому світі: файли, API, браузер, shell |
| **Немає пам'яті** | Після завершення сесії — повний скид. Кожен новий запит починається з нуля |
| **Не планує** | Не вміє самостійно розбивати задачу на кроки і виконувати їх послідовно |
| **Без feedback loop** | Не перевіряє власні результати. Відсутній цикл зворотного зв'язку |

## Визначення агента

> **АГЕНТ = LLM + ПАМ'ЯТЬ + ІНСТРУМЕНТИ + ЦИКЛ**

Агент — це система, яка використовує LLM як «мозок» для прийняття рішень, але доповнює його пам'яттю, інструментами та циклом: **подумай → зроби → перевір**.

---

## З чого складається агент

### 1. LLM — мозок агента

- **Інтерпретує** — розуміє запит, визначає мету, перетворює природну мову на структурований намір
- **Вирішує** — обирає наступну дію: відповісти, викликати інструмент або уточнити деталі
- **Формулює** — складає відповідь або запит до інструменту. Мова — єдиний інтерфейс LLM
- **Оцінює** — аналізує результат кожної дії, вирішує чи достатньо чи потрібен ще один крок

### 2. Tools — руки агента

LLM не виконує дії сам. Він формулює намір — система виконує і повертає результат.

```
① LLM: потрібен інструмент X з параметрами Y
② Система виконує виклик інструменту
③ Результат повертається до LLM
④ LLM аналізує і вирішує наступний крок
```

| Інструмент | Призначення |
|---|---|
| Google Search | Пошук в інтернеті |
| Code Executor | Виконання коду |
| Database | Запит до бази даних |
| Email / Slack | Відправка повідомлень |
| Code Function | Довільна функція в коді |
| REST API | Будь-який зовнішній сервіс |

### 3. Memory — записник агента

| Тип | Опис |
|---|---|
| **Short-term** | Контекст поточної розмови: що вже зроблено, які результати отримано. Обмежена розміром контекстного вікна. Зникає після сесії |
| **Long-term** | Збережені факти, минулі розмови, уроки з попереднього досвіду. Зберігається зовні у БД або векторному сховищі. Персистентна між сесіями |

### 4. Planning — стратегія агента

| Тип планування | Принцип | Аналогія |
|---|---|---|
| **З фідбеком** | Адаптивний план: крок → результат → корекція → наступна дія | Водій з GPS: перераховує маршрут після кожного повороту |
| **Без фідбеку** | Фіксований план: кроки визначені наперед, без відхилень | Рецепт: крок 1 → крок 2 → крок 3 → результат |

## Спектр автономності

| Рівень | Тип | Опис | Приклади |
|---|---|---|---|
| **0** | Статичний чат-бот | Правила та decision tree. Скриптований діалог без AI | IVR, FAQ-бот |
| **1** | LLM чат-бот | Відповідає мовою, розуміє контекст. Але не діє | ChatGPT (базовий) |
| **2** | LLM + інструменти | Може викликати інструменти. Людина задає кроки | ChatGPT + plugins |
| **3** | Автономний агент | Сам планує, вибирає інструменти, перевіряє результат | LangChain |
| **4** | Мультиагентна система | Кілька агентів координують роботу між собою | LangGraph |

## Цикл ReAct: Reasoning + Acting

### Три кроки

```
① THOUGHT (Міркування)
   Агент отримує задачу і "думає вголос":
   що потрібно зробити? яка інформація відсутня? який інструмент допоможе?

② ACTION (Дія)
   На основі міркувань агент обирає конкретну дію:
   пошук, запит до БД, виконання коду, звернення до API

③ OBSERVATION (Спостереження)
   Агент отримує результат дії і аналізує:
   чи достатньо інформації? чи задача вирішена?
   Якщо ні — цикл повторюється з нового Thought
```

### ReAct на прикладі: пошук рейсу

**Користувач:** Знайди мені найдешевший рейс з Варшави до Токіо на наступний тиждень

```
THOUGHT ①
Мені потрібно знайти рейси. Я маю інструмент для пошуку авіаквитків.
Але спершу потрібні точні дати — що таке "наступний тиждень"?

ACTION ①
Подивитися календар. Визначити дати наступного тижня.

OBSERVATION ①
Наступний тиждень — 10–16 березня. Дати відомі.

THOUGHT ②
Тепер маю дати. Шукаю рейси Варшава → Токіо на 10–16 березня.

ACTION ②
Пошук авіаквитків Варшава → Токіо, дати 10–16 березня.

OBSERVATION ②
Знайдено 5 рейсів. Найдешевший: Turkish Airlines, $420, з пересадкою в Стамбулі.

THOUGHT ③
Маю результат. Задача вирішена. Формую відповідь для користувача.

FINAL ANSWER
Найдешевший рейс з Варшави до Токіо на 10–16 березня — 
Turkish Airlines за $420, з пересадкою в Стамбулі.
```

## Розширені механізми мислення

| Механізм | Опис | Приклад |
|---|---|---|
| **Self-Reflection** | Агент перевіряє власну відповідь: чи логічна, чи без протиріч, чи повністю відповідає на запит | «Я відповів про ціну, але не вказав деталі пересадки» |
| **Self-Critique** | Агент оцінює якість роботи: чи можна зробити краще? | «Відповідь коректна, але занадто технічна для користувача» |
| **Planning Ahead** | Агент думає на кілька кроків уперед і готує запасні стратегії | «Якщо пошук не дасть результату — спробую інший інструмент» |

## Як програмується поведінка агента

Системний промпт — контракт з агентом. Три ключові елементи:

| Елемент | Питання | Приклади |
|---|---|---|
| **Role** | Хто ти? | «Ти — фінансовий аналітик, 10 років досвіду» / «Ти — junior Python developer» |
| **Goal** | Чого досягти? | «Знайди ризики у квартальному звіті» / «Напиши unit-тести для авторизації» |
| **Constraints** | Чого НЕ робити? | «Не давай фінансових порад без застереження» |

> **Guardrails:** Без чітких обмежень агент може «піти не туди» — витратити бюджет API, видалити дані або дати небезпечну пораду.

## Стан ринку (2025–2026)

> 2025–2026 — рік, коли агенти переходять від хайпу до реальних бізнес-задач.

- **38%** компаній пілотують агентні рішення *(Deloitte, 2025)*
- **11%** мають агентів у production *(Deloitte, 2025)*
- **40%** корпоративних додатків матимуть вбудованих task-specific AI агентів до кінця 2026 року *(Gartner, 2026)*

> **Ключовий меседж:** Більшість пілотів провалюються не через технологію. Провалюються через відсутність інженерного підходу — чіткої архітектури, контролю, оцінки якості. Розрив між демо та production — головний виклик індустрії.

## Підсумки

- **Агент vs Чат-бот** — агент це LLM із пам'яттю, інструментами та плануванням. Він діє в циклі, а не просто відповідає на одне запитання
- **Компоненти агента** — LLM (мозок) + Tools (руки) + Memory (записник) + Planning (стратегія). Разом утворюють автономного агента
- **Цикл ReAct** — Thought → Action → Observation — базовий цикл. Self-reflection та self-critique дозволяють агенту покращуватись у процесі
- **Prompt Engineering** — системний промпт це контракт з агентом. Role + Goal + Constraints. Без guardrails агент непередбачуваний
- **Агенти в production** — 38% пілотують, 11% у production. Пілоти провалюються не через технологію — через брак архітектури та контролю

> **Головний висновок:** Агент — інженерна система. Потребує чіткого промпту, надійних інструментів, обдуманої пам'яті та guardrails.
