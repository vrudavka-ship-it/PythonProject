Tool Calling — механізм, через який LLM взаємодіє із зовнішнім світом: генерує структурований запит (JSON), а ваш код виконує відповідну дію і повертає результат.
Що включає: custom-функції (API-виклики, БД-запити), вбудовані інструменти (code interpreter, file search, web browsing).
Як працює: ви описуєте доступні tools у JSON Schema → LLM обирає потрібний tool і генерує аргументи → ваш код виконує → результат повертається в LLM.
Еволюція: парсинг регулярками (2022) → function calling (OpenAI, 2023) → tool use як стандарт індустрії (2023-24) → structured outputs (серпень 2024).

import json
from openai import OpenAI

client = OpenAI()

messages = [
  {"role": "system", "content": "You are a weather assistant."},
  {"role": "user", "content": "What is the weather in Kyiv?"},
]

response = client.responses.create(
  model="gpt-5.4",
  input=messages,
  tools=[
    {
      "type": "function",
      "name": "get_weather",
      "description": "Get weather for a city",
      "parameters": {...}
    }
  ]
)
tool_call = response.output[0]

args = json.loads(tool_call.arguments)
result = get_weather(**args)

tool_calls містить назву функції та аргументи, що обрала модель.
КРОК 3 — ВИКОНАННЯ
ВИ розпаковуєте аргументи і викликаєте реальну Python-функцію.

LANGCHAIN – TOOLS
from langchain_core.tools import tool

# @tool decorator — minimal tool definition
@tool
def get_weather(city: str) -> str:
    """Return current weather for a city."""
    return f"Weather in {city}: 22C, sunny"

# Tool with multiple parameters
@tool
def search_db(query: str, limit: int = 5) -> list:
    """Search database records by query.
    Args: query: search string. limit: max results.""")
    return db.search(query, limit)[:limit]

# Bind tools to model
llm_with_tools = llm.bind_tools([get_weather, search_db])
Як LangChain бачить інструмент?
@tool читає ім'я функції, docstring та type hints — і автоматично генерує JSON-схему для LLM.
3 обов'язкові елементи
ім'я — назва функції
docstring — опис для LLM
type hints — типи параметрів
bind_tools()
Прив'язує список інструментів до моделі. Модель може викликати їх при потребі.

LANGCHAIN – CHAINS (LCEL)
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. Build components
prompt = ChatPromptTemplate.from_messages([
    ("system","You are a {role}. Be concise."),
    ("human","{question}")
])
model = ChatOpenAI(model="gpt-5.4")
parser = StrOutputParser()

# 2. Compose via | — this is an LCEL chain
chain = prompt | model | parser

# 3. Invoke with input variables
result = chain.invoke({
    "role": "Python expert",
    "question": "What is a decorator?"
})
# result is a plain string, not AIMessage!
Що таке LCEL?
LangChain Expression Language — декларативний спосіб будувати конвеєри через оператор |.
Потік даних
dict → prompt → AIMessage
AIMessage → model → str
Переваги LCEL
Автоматичний streaming
Підтримка async/await
Трасування через LangSmith
Паралельне виконання

LANGCHAIN – MEMORY
from langchain.agents import create_agent
from langgraph.checkpoint.memory import MemorySaver

# Memory is built into create_agent via checkpointer
agent = create_agent(
    model="gpt-5.4",
    tools=[get_weather, search_db],
    checkpointer=MemorySaver(),
    system_prompt="You are a helpful assistant."
)

# thread_id scopes history — each user gets their own
config = {"configurable": {"thread_id": "alice"}}

resp1 = agent.invoke(
    {"messages": [{"role": "user", content: "My name is Alice."}]},
    config=config
)

# Agent remembers the conversation automatically
resp2 = agent.invoke(
    {"messages": [{"role": "user", content: "What is my name?"}]},
    config=config
)
# -> "Your name is Alice."

TOOL SEARCH – THE SCALE PROBLEM
СИТУАЦІЯ
Агент має доступ до сотень інструментів.
Статичний список: всі інструменти передаються
до контексту LLM при кожному виклику.

НАСЛІДОК
1 опис інструменту ≈ 100 токенів.
500 інструментів → 50 000 токенів лише для інструментів.
Модель губиться серед варіантів,
вартість зростає, якість падає.
МАСШТАБ
10 інструментів ≈ 3 тис. токенів
100 інструментів ≈ 30 тис. токенів
500+ інструментів → переповнення контексту
РІШЕННЯ
Векторне сховище індексує описи інструментів.
Агент отримує Top-K за потреби.
3–5 інструментів замість сотень.
ПОРІГ
20+ інструментів — динамічний пошук
перевершує статичний список.

TOOL SEARCH – HOW IT WORKS
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings

# Index all tools in vectorstore
tool_docs = ["search_web: searches the web", ...]
vectorstore = Chroma.from_texts(tool_docs, OpenAIEmbeddings())

# On-demand retrieval during agent run
query = "Find weather in Kyiv"
relevant = vectorstore.similarity_search(query, k=3)
# ['search_web', 'get_weather', 'query_api'] <- 3 of 500

# Agent gets only the relevant tools
def agent_step(query):
    tools = vectorstore.similarity_search(query, k=5)
    return llm.call(query, tools=tools)

CODE CALLING – SANDBOX
import subprocess

def run_in_sandbox(code: str) -> dict:
    # Docker: isolated, no network, timeout=30s
    res = subprocess.run(
        ["docker", "run", "--rm", "--network=none"],
        input=code, capture_output=True, timeout=30
    )
    return {"stdout": res.stdout, "stderr": res.stderr}

# Example: agent received a task
code = llm.generate_code("Find the sum from 1 to 100")
out = run_in_sandbox(code)
# out = {'stdout': '5050', 'stderr': ''}

# Self-check: if stderr exists, LLM fixes it
if out["stderr"]:
    fixed = llm.invoke(
      f"Fix this code:\n{code}\nError:\n{out[’stderr’]}"
    )
    out = run_in_sandbox(fixed)

ПІДСУМКИ
Агент — це не магічна сутність. Це звичайний софт, де LLM приймає рішення, а детермінований код їх виконує.
Все починається з tool calling: NL → JSON → ваш код → результат назад у LLM. Решта — надбудова.
Фреймворк прискорює старт, але ви маєте володіти своїм промптом, контекстом і control flow.
Контекст — найцінніший ресурс. Хто краще керує context window — той будує кращих агентів.
