## Що таке Generative AI?

**Generative AI** — клас моделей штучного інтелекту, здатних створювати новий контент: текст, зображення, аудіо, відео та код на основі патернів, вивчених з навчальних даних.

### Відмінність від класичного ML

| | Класичний ML | Generative AI |
|---|---|---|
| **Підхід** | `P(Y│X)` — визначає мітку за вхідними даними | `P(X│context)` — створює новий контент |
| **Моделі** | Здебільшого дискримінативні | Генеративні |
| **Навчання** | Часто потребує розмічених даних (supervised) | Self-supervised на великих корпусах |
| **Результат** | Мітки, числа, категорії | Новий контент будь-якого типу |
| **Приклади** | Random Forest, SVM, XGBoost, CNN | GPT, Claude, DALL-E, Stable Diffusion |

**Ключова ідея** — зсув від розпізнавання до створення:
- `P(Y│X)` — класичний підхід: «що це?»
- `P(X)` — генеративний: вивчити розподіл і створити нове
- `P(X | context)` — умовна генерація: відповідь залежить від промпту

## Моделі генерації

| Тип | Принцип | Для чого |
|---|---|---|
| **Autoregressive (LLM)** | Пише текст слово за словом. Кожне нове слово обирається на основі попередніх | Чат-боти, переклад, написання коду |
| **GANs** | Дві мережі змагаються: одна створює підробки, інша намагається їх розпізнати | Реалістичні обличчя, deepfakes |
| **Diffusion Models** | Бере випадковий шум і крок за кроком «очищує» його, поки не вийде картинка | Генерація зображень, відео |
| **VAEs** | Вчиться розуміти суть даних, стискаючи їх до ключових ознак | Генерація нових облич, голосу, форм |

## Генерація тексту: LLM

Як створюють LLM (3 етапи):
1. **Pre-training** — трильйони токенів тексту з інтернету, книг, коду
2. **Fine-tuning (SFT)** — навчання на прикладах діалогів: як відповідати правильно та безпечно
3. **RLHF** — люди оцінюють відповіді, модель вчиться відповідати якісніше

**Ключові поняття:**
- **Context window** — скільки тексту модель «бачить» одночасно (4K → 128K → 1M+ токенів)
- **Temperature** — контроль «креативності»: 0 = детерміновано, 1 = різноманітно
- **Hallucinations** — модель впевнено генерує неправдиву інформацію

### Авторегресивна генерація

```
P(xₜ | x₁, x₂, ..., xₜ₋₁) — кожен токен обирається на основі всіх попередніх

Київ          → p = 0.31
Київ це       → p = 0.47
Київ це столиця    → p = 0.52
Київ це столиця України → p = 0.68  → генерація завершена
```

## Генерація зображень

**Додаткові можливості:**
- **Inpainting** — замінити частину зображення (змінити фон)
- **Img2img** — перетворити ескіз на готову ілюстрацію
- **Upscaling** — збільшити роздільність без втрати якості

**Сучасні моделі:**
- **GPT Image** — лідер за рейтингом LM Arena, найкращий рендеринг тексту
- **Midjourney** — популярний серед дизайнерів
- **Nano Banana Pro** — морфить кілька зображень, дотримується складних промптів

**Обмеження:** текст на зображеннях, руки/пальці, точний контроль композиції

### Як працює дифузія (Stable Diffusion / DALL-E)

```
Текстовий промпт
    ↓
Text Encoder (CLIP / T5)
    ↓
Випадковий шум (латентний простір 64×64×4)
    ↓
U-Net / DiT — Деноїзинг (20–50 ітерацій, classifier-free guidance)
    ↓
VAE Decoder (латент → пікселі: 64×64 → 512×512)
    ↓
Готове зображення 512×512
```

**Ключова ідея:** модель працює в латентному просторі (стисненому) — це в 64× менше пікселів → генерація за секунди. Модель **не малює** картинку з нуля — вона навчилась видаляти шум під керуванням тексту.

## Архітектура Transformer

### Self-Attention

Transformer (Google, 2017) — архітектура нейромережі, що бачить всі слова **одночасно** (на відміну від RNN/LSTM які читали послідовно).

**Три ролі кожного токена:**
- **Query** — «яку інформацію я шукаю від інших?»
- **Key** — «чим я можу бути корисний іншим?»
- **Value** — «яку саме інформацію я передаю»

Кроки: `Q·K → оцінки → Softmax (ваги) → зважена сума V → контекст`

### Multi-Head Attention

Кілька механізмів attention (голів) працюють паралельно — кожна фокусується на різних типах зв'язків між токенами. Результати конкатенуються і проходять через лінійний шар.

### Positional Encoding

Вектор, що додається до ембедінгу кожного токена і кодує його позицію. Transformer обробляє всі токени паралельно, без вбудованого поняття порядку — позиційне кодування це компенсує.

### Три типи архітектур

| Тип | Моделі | Принцип | Задачі |
|---|---|---|---|
| **Encoder-only** | BERT, RoBERTa | Двонаправлений контекст, MLM | Класифікація, NER, семантичний пошук |
| **Decoder-only** | GPT, Claude, LLaMA | Causal (ліво→право), авторегресійний | Генерація тексту, чат, код |
| **Encoder-Decoder** | T5, BART | Encoder розуміє вхід, decoder генерує вихід | Переклад, сумаризація |

## Токенізація та контекст

**Токенізація** — процес розбиття тексту на менші одиниці (токени):
```
"Я люблю каву"  →  [Я] [люб] [лю] [кав] [у]  →  [142, 8834, 1055, 7291, 483]
```

- Токен — не завжди ціле слово, може бути частина слова або символ
- Алгоритми: BPE (GPT), WordPiece (BERT), SentencePiece (T5, LLaMA)
- Словник: 32K–100K унікальних токенів

**Контекстне вікно** — макс. кількість токенів (input + output) за один запит. Обмежене O(n²) складністю attention та GPU пам'яттю. Оптимізації: FlashAttention, KV-cache, Sparse attention.

## Тренування LLM

### Pre-training (база знань)

- Self-supervised навчання на гігантських корпусах (книги, вебсайти, код, Wikipedia)
- LLaMA 3 — 15 трильйонів токенів, тисячі GPU H100/A100
- Бюджет: $10M–$100M+ на один run, місяці тренування
- Результат — «base model»: розуміє мову, але не оптимізована для діалогу

### SFT + RLHF (alignment)

1. **SFT (Supervised Fine-Tuning)** — навчання на розмічених прикладах діалогів
2. **RLHF** — люди порівнюють відповіді → тренується reward model → LLM оптимізується через PPO

**Сучасні альтернативи:**
- **DPO** — без окремої reward model
- **RLAIF** — AI замість людей для оцінки
- **Constitutional AI** (Anthropic) — принципи замість прямих оцінок

### Масштаб тренування

- **Scaling Laws** — продуктивність передбачувано зростає з параметрами, даними та compute
- GPT-4 ~ $100M на тренування, LLaMA 3 405B ~ 31M GPU-годин
- **Emergent Abilities** — при масштабі з'являються chain-of-thought, кодинг, математика

## Підсумки

- **Generative AI vs класичний ML** — LLM, GAN, Diffusion, VAE
- **Модальності** — текст, зображення, аудіо, відео
- **Transformer** — self-attention, multi-head, positional encoding
- **Архітектури** — encoder-only, decoder-only, encoder-decoder
- **Токенізація, ембедінги, контекстне вікно** — як LLM обробляє текст

> **Головний висновок:** LLM — потужний фундамент для мультиагентних систем, але потребує розуміння обмежень.
