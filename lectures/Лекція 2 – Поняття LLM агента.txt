МОДЕЛІ ГЕНЕРАЦІЇ
ТО ЩО ТАКЕ LLM АГЕНТ?

ЩО НЕ ТАК З LLM?
ЗАСТАРІЛІ ДАНІ
Знання зафіксовані на момент навчання. Немає доступу до актуальної інформації.
НЕМАЄ ДІЙ
Не може виконувати операції у зовнішньому світі: файли, API, браузер, shell.
НЕМАЄ ПАМ'ЯТІ
Після завершення сесії — повний скид. Кожен новий запит починається з нуля.
НЕ ПЛАНУЄ
Не вміє самостійно розбивати задачу на кроки і виконувати їх послідовно.
БЕЗ FEEDBACK LOOP
Не перевіряє власні результати. Відсутній цикл зворотного зв'язку.

ВИЗНАЧЕННЯ АГЕНТА
АГЕНТ = LLM + ПАМ'ЯТЬ + ІНСТРУМЕНТИ + ЦИКЛ
Агент — це система, яка використовує LLM як "мозок" для прийняття рішень, але доповнює його пам'яттю, інструментами та циклом: подумай → зроби → перевір

З ЧОГО СКЛАДАЄТЬСЯ АГЕНТ
1
LLM
Мозок агента. Розуміє мову, міркує і вирішує — що зробити, який інструмент викликати, як оцінити результат.
2
TOOLS
Руки агента. Пошук, код, API. Все, що LLM не може зробити сам, але може попросити систему виконати.
3
MEMORY
Записник агента. Short-term — контекст розмови. Long-term — факти та досвід у зовнішній базі даних.
4
PLANNING
Стратегія агента. Розбиває задачу на кроки. Адаптує план або слідує фіксованому сценарію.

LLM — МОЗОК АГЕНТА
ІНТЕРПРЕТУЄ
Розуміє запит. Визначає мету. Перетворює природну мову на структурований намір.
ВИРІШУЄ
Обирає наступну дію: відповісти, викликати інструмент або уточнити деталі.
ФОРМУЛЮЄ
Складає відповідь або запит до інструменту. Мова — єдиний інтерфейс LLM.
ОЦІНЮЄ
Аналізує результат кожної дії. Вирішує — достатньо чи потрібно ще один крок.

TOOLS — РУКИ АГЕНТА
ЯК ЦЕ ПРАЦЮЄ
LLM не виконує дії сам. Він формулює намір — система виконує і повертає результат.

③ Результат повертається до LLM
④ LLM аналізує і вирішує наступний крок

MEMORY — ЗАПИСНИК АГЕНТА
SHORT-TERM
Контекст поточної розмови: що вже зроблено, які результати отримано. Обмежена розміром контекстного вікна LLM. Зникає після завершення сесії.
1
LONG-TERM
Збережені факти, минулі розмови, уроки з попереднього досвіду. Зберігається зовні у базі даних або векторному сховищі. Персистентна між сесіями.
2

PLANNING — СТРАТЕГІЯ АГЕНТА
З ФІДБЕКОМ
Адаптивний план. Агент робить крок, бачить результат і коригує наступну дію.
Як водій з GPS: перераховує маршрут після кожного повороту.
дія → результат → корекція → наступна дія
БЕЗ ФІДБЕКУ
Фіксований план. Агент складає послідовність кроків заздалегідь і виконує без відхилень.
Як рецепт: кроки визначені наперед, відхилень від сценарію немає.
крок 1 → крок 2 → крок 3 → результат

ЦИКЛ REACT: REASONING + ACTING
1
THOUGHT
Міркування
Агент отримує задачу і "думає вголос": що потрібно зробити? Яка інформація відсутня? Який інструмент допоможе вирішити цей крок?
2
ACTION
Дія
На основі міркувань агент обирає конкретну дію: пошук в інтернеті, запит до бази даних, виконання коду або звернення до API.
3
OBSERVATION
Спостереження
Агент отримує результат дії і аналізує: чи достатньо інформації? Чи задача вирішена? Якщо ні — цикл повторюється з нового Thought.

REACT НА ПРИКЛАДІ: ПОШУК РЕЙСУ
КОРИСТУВАЧ
Знайди мені найдешевший рейс з Варшави до Токіо на наступний тиждень
THOUGHT  ①
Мені потрібно знайти рейси. Я маю інструмент для пошуку авіаквитків. Але спершу потрібні точні дати — що таке "наступний тиждень"?
ACTION  ①
Подивитися календар. Визначити дати наступного тижня.
OBSERVATION  ①
Наступний тиждень — 10–16 березня. Дати відомі.
THOUGHT  ②
Тепер маю дати. Шукаю рейси Варшава → Токіо на 10–16 березня за допомогою інструменту пошуку квитків.

REACT НА ПРИКЛАДІ: ПОШУК РЕЙСУ
ACTION  ②
Пошук авіаквитків Варшава → Токіо, дати 10–16 березня.
OBSERVATION  ②
Знайдено 5 рейсів. Найдешевший: Turkish Airlines, $420, з пересадкою в Стамбулі.
THOUGHT  ③
Маю результат. Задача вирішена. Формую відповідь для користувача.
FINAL ANSWER
Найдешевший рейс з Варшави до Токіо на 10–16 березня — Turkish Airlines за $420, з пересадкою в Стамбулі.

РОЗШИРЕНІ МЕХАНІЗМИ МИСЛЕННЯ
SELF-REFLECTION
Самоперевірка
Агент перевіряє власну відповідь: чи логічна, чи без протиріч, чи повністю відповідає на запит?
"Я відповів про ціну, але не вказав деталі пересадки."
SELF-CRITIQUE
Самооцінка якості
Агент оцінює якість роботи — чи можна зробити краще? Вибір між кількома варіантами відповіді.
"Відповідь коректна, але занадто технічна для користувача."
PLANNING AHEAD
Планування наперед
Агент думає на кілька кроків уперед і готує запасні стратегії на випадок провалу поточного підходу.
"Якщо пошук не дасть результату — спробую інший інструмент."

ЯК ПРОГРАМУЄТЬСЯ ПОВЕДІНКА АГЕНТА
ROLE
Хто ти?
Задає особистість, тон і рівень експертизи агента.

"Ти — фінансовий аналітик, 10 років досвіду"
"Ти — junior Python developer"
GOAL
Чого досягти?
Визначає конкретну ціль і критерій успішного завершення.
"Знайди ризики у квартальному звіті"
"Напиши unit-тести для авторизації"
CONSTRAINTS
Чого НЕ робити?
Захисні рейки: межі дозволеного для агента.

"Не давай фінансових порад без застереження"
"Завжди перепитуй перед видаленням даних" (НЕ РОБІТЬ ТАК)
GUARDRAILS
Без чітких обмежень агент може «піти не туди» — витратити бюджет API, видалити дані або дати небезпечну пораду.

ПІДСУМКИ
АГЕНТ vs ЧАТ-БОТ

Агент — це LLM із пам'яттю, інструментами та плануванням. Він діє в циклі, а не просто відповідає на одне запитання.
КОМПОНЕНТИ АГЕНТА

LLM (мозок) + Tools (руки) + Memory (записник) + Planning (стратегія). Разом вони утворюють автономного агента.
ЦИКЛ REACT

Thought → Action → Observation — базовий цикл. Self-reflection та self-critique дозволяють агенту покращуватись у процесі.
PROMPT ENGINEERING

Системний промпт — контракт з агентом. Role + Goal + Constraints. Без guardrails агент непередбачуваний.
АГЕНТИ В PRODUCTION

38% пілотують, 11% у production [*]. Пілоти провалюються не через технологію — через брак архітектури та контролю.
ГОЛОВНИЙ ВИСНОВОК

Агент — інженерна система. Потребує чіткого промпту, надійних інструментів, обдуманої пам'яті та guardrails.
[*] серед опитаних Deloitte
